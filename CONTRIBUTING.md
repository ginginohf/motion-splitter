# Участие в Motion Splitter

Репозиторий готовится к первому публичному релизу. Установка и команды проверки:
[DEVELOPMENT.md](docs/DEVELOPMENT.md). План: [ROADMAP.md](docs/ROADMAP.md).

## Ошибки и предложения

После публикации используйте **Issues → New issue**. Выберите форму «Ошибка»
или «Предложение». Перед созданием проверьте существующие Issues.
Для ошибки важны воспроизводимые шаги, версия, ОС, параметры и очищенный журнал.
Для функции — задача пользователя и пример желаемого поведения.

Не размещайте чужие/приватные видео, секреты и неочищенные отчёты. Для примеров
используйте синтетические ролики из `tools/generate_fixtures.py` или материал,
которым вправе публично делиться.

## Изменения кода

1. Создайте ветку с одной понятной задачей.
2. Сохраните работу старых настроек/пресетов, если меняете схему.
3. Не обращайтесь к Tk из рабочего потока и не обходите общий механизм отмены.
4. Не перезаписывайте исходники, результаты других запусков и чужие временные папки.
5. Запустите подходящие проверки. Для обработки — `python tools/check_ci.py`,
   для GUI дополнительно `python tools/check_ci.py --gui-only`.
6. Обновите документацию при изменении поведения. Для GUI приложите чистые
   скриншоты и укажите проверенную ОС; для упаковки проверьте целевую систему.
7. Откройте Pull Request: опишите проблему, поведение после изменения,
   выполненные проверки и ограничения.

Для правок только текста достаточно проверить ссылки, команды и соответствие
названий текущему интерфейсу. Не нужно запускать всю обработку видео заново.
Непройденную проверку укажите явно; не скрывайте её через безусловный пропуск.
