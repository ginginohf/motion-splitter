# Пункт 6 — настройки и пресеты

## Изменения

- Новый модуль `settings_store.py`: схема версии 1, нормализация, проверка типов
  и диапазонов, миграция, восстановление и атомарная запись.
- Значения по умолчанию копируются глубоко. Словари пресетов разных экземпляров
  настроек больше не разделяются.
- Числовые поля проверяются на конечность и диапазон; целые не принимают
  дроби или bool. Логические поля требуют bool; списки разрешений, моделей и
  типов источника проверяются. Диапазоны опубликованы в README.
- Старый формат без версии дополняется полями. Пересчёт старого суммарного
  порога >255 сохранён для невeрсионированных настроек и пресетов; применяется
  только при миграции, не к версии 1.
- Повреждённый JSON, поля или пресеты резервируются побайтно рядом с файлом.
  Корректные значения сохраняются, некорректные восстанавливаются по умолчанию;
  сообщения доступны в журнале. Если резервную копию сохранить невозможно,
  ошибка не скрывается и исходник не перезаписывается.
- Более новая версия схемы отклоняется при чтении и записи. Неизвестные
  текущей программе настройки будущей версии не уничтожаются.
- Запись выполняется в уникальный временный файл в том же каталоге, с `flush`,
  `fsync` и `os.replace`. При ошибке временный файл очищается. Только после
  успешной записи обновляется `App.settings` — единый сохранённый снимок в памяти.
- `collect_settings` собирает и проверяет текущие Tk-поля перед сохранением,
  запуском, сохранением пресета и сменой темы. Смена темы больше не записывает
  устаревшие значения остальных полей.
- Пять параметров Real-ESRGAN используют общие Tk-переменные на двух вкладках.
  Добавлена кнопка сохранения на вкладку улучшения; сообщение показывается
  в журнале выбранной вкладки. Обе кнопки сохранения отключены во время задачи.
- Оба режима сохраняют проверенные параметры перед запуском. При ошибке
  параметров/записи рабочий поток не запускается.
- Сохранение, применение и удаление пресетов защищены от ошибок. Сбой записи
  не меняет сохранённый снимок в памяти. Имена после удаления пробелов по краям
  должны содержать 1–100 символов; частичные старые пресеты получают все поля.
- При старте восстановленный выбранный пресет больше не применяется повторно
  поверх последних вручную изменённых и сохранённых параметров.

## Проверки

`python -m unittest discover -s tests -q`: 57 тестов прошли.

11 новых сценариев: независимые defaults; миграция старых настроек/частичного
пресета; неверные числа; неверные перечисления и bool; побайтная резервная копия
повреждённого JSON; сохранение корректных полей при восстановлении; повреждённый
корень JSON; защита будущей версии; сбой атомарной замены; отсутствие записи
при неверных параметрах; обновление памяти только после успешной записи.

`tools/check_gui_settings.py`: настоящий Tkinter, временный файл настроек.
Проверены восстановление последних правок вместо старого пресета, общие поля
двух вкладок, сохранение из вкладки улучшения, смена темы без потери правок,
сохранение/применение/удаление пресета, отказ сохранения и запуска при NaN.

`tools/check_gui_threads.py`: после изменений обе задачи последовательно
завершились, конфликтующий запуск заблокирован, ошибок Tkinter не было.

## Границы

Схема проверяет все поля, включая отключённые элементы. Совместимость конкретной
модели, масштаба и GPU — пункт 12. Атомарная замена не является разрешением
конфликтов нескольких одновременно запущенных экземпляров приложения:
последнее успешное сохранение определяет содержимое файла.
Миграция записывается при явном сохранении/запуске, а не автоматически при чтении.
Восстановительные копии остаются пользователю; их автоудаление не выполняется.
Проверки выполнены на macOS; Windows/Linux на этом этапе не проверены.
