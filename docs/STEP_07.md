# Пункт 7 — отделение обработки от интерфейса

## Изменения

- Монолит разделён на `gui.py`, `video_analysis.py`, `video_export.py`,
  `video_enhance.py` и `processing.py`. Настройки, запуск процессов и файловая
  безопасность остаются в выделенных на предыдущих этапах модулях.
- `motion_splitter.py` стал небольшой точкой входа. Способы запуска сохранены;
  функции анализа/экспорта доступны через прежний импорт. `App` загружается
  лениво при явном обращении; простой импорт функций ядра не импортирует GUI.
- Поиск FFmpeg/Real-ESRGAN перенесён в `external_tools.py`. Поиск рядом с
  приложением сохранился: модули находятся в одном корневом каталоге проекта.
- Методы рабочих задач вынесены из App в обычные функции `run_split` и
  `run_enhance`. Они не обращаются к Tkinter и не требуют экземпляра App.
- В `job_contracts.py` определены `TaskContext`, `EventSink`, `TaskEvent` и
  неизменяемый `JobResult`. Контекст содержит только обработчик событий и
  сигнал отмены. Функции задач возвращают результат и отправляют итоговое событие.
- Освобождение VideoCapture при ошибке/отмене в анализе и автонастройке сохранено.
  Для `get_video_duration` также добавлен `try/finally`, включая неоткрытый файл
  и исключение при чтении метаданных.
- Тесты и проверочные скрипты теперь обращаются к владельцам функций в новых
  модулях. Имитации инструментов устанавливаются на уровне orchestration,
  а GUI-проверки используют `gui.py`.

## События и результат

События сохраняют совместимый формат `(kind, payload)`:

| kind | payload |
|---|---|
| info | Строка журнала |
| total_init | Число входных файлов |
| file_name | Имя текущего файла |
| file_progress | Пара `(кадр, число кадров)` |
| total_progress | Пара `(обработано, всего)` |
| preview_frame | Кадр BGR, номер кадра, показатель движения |
| done / cancelled | Число обработанных файлов |
| error | Сообщение об ошибке |

`JobResult` содержит status (`done`, `cancelled`, `error`), processed, total,
output_directory и error. При отмене до создания папки её значение — None.
Это общий результат задачи; полный отчёт по отдельным файлам — пункт 14.

## Проверки

60 автоматических тестов прошли. Три новые проверки:

- В отдельном процессе запрещены импорты `gui`, `tkinter` и `PIL.ImageTk`.
  При этом выполняется настоящая задача анализа/экспорта FFmpeg, проверяется

  проверяются результаты отмены и ошибки и совместимый импорт motion_splitter.
- VideoCapture освобождается при невозможности открыть файл и при ошибке
  получения длительности.
- Анализ освобождает VideoCapture при исключении пользовательского callback.

`tools/check_baseline.py` прошёл: интервалы и автопороги совпадают с предыдущим
этапом, экспорт работает. Известный дефект движения в конце видео не изменён.

Проверки настоящего Tkinter прошли: `check_gui_threads.py`,
`check_gui_settings.py`, `check_gui_close.py`. Проверены обе задачи, настройки
и пресеты, закрытие окна во время работы настоящего FFmpeg.

Проверено на macOS. Настоящий GPU-апскейл и Windows/Linux пока не проверены.
