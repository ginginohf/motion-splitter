# Пункт 2 — защита исходников и результатов

## Изменения

- Каждая задача обеих вкладок создаёт новую папку запуска через `mkdtemp`.
  Повторные и одновременные запуски не делят выходные каталоги.
- Внутри запуска каждому исходнику выделяется подпапка с полным именем:
  `clip.mp4` и `clip.mov` не конфликтуют.
- Файлы экспорта и апскейла создаются в уникальной скрытой временной папке
  рядом с итоговым файлом. Расширение временного видео сохранено для выбора
  контейнера внешней программой.
- После успешного выхода программы и проверки непустого файла итоговое имя
  публикуется атомарной жёсткой ссылкой. Существующий путь не заменяется,
  в том числе если другой процесс создал его непосредственно перед публикацией.
- Совпадение с исходником, существующие файлы/каталоги, символические ссылки
  (включая оборванные) и жёсткие ссылки отклоняются до обработки.
- Покадровый апскейл использует только свои уникальные каталоги. Старые
  `_frames` / `_frames_up` и остатки чужих запусков не удаляются.
- FFmpeg получает `-n`, а не `-y`. Повтор той же команды после любой ошибки
  убран из сохранения, чтобы не выполнять повторные операции записи.
- Выбор папки исключает собственные результаты: по маркеру/имени каталога,
  а для старых файлов — по окончаниям имени. Символические ссылки на результаты
  также исключаются. Явный выбор файла разрешает осознанную повторную обработку.
- Исправлен путь импорта нового модуля для `tools/run_local.py`.

## Проверки

Команда: `python -m unittest discover -s tests -v`.

16 тестов: публикация только после завершения; сбой/пустой результат; защита
существующих файлов и алиасов исходника; конфликт в момент публикации; отказ
файловой системы; изоляция запусков; фильтрация папки; успех и сбой прямого
апскейла; сбой каждого из трёх этапов покадрового апскейла; сохранность старых
кадров; повторный запуск отдельной вкладки; реальные экспорты FFmpeg и пакетная
задача нарезки без открытия GUI.

Реальный FFmpeg проверяется на синтетическом видео: повторные экспорты,
полная копия, декодирование результатов, наличие аудио, неизменность байтов
исходника и предыдущего результата. Проверяются пути с кириллицей/пробелами
и ошибка на повреждённом входном видео.

Real-ESRGAN заменён управляемой имитацией внешнего процесса: проверяется
безопасность файлов и очистки, а не качество/совместимость модели или GPU.

Все 16 тестов прошли. Дополнительно прошли `tools/check_baseline.py`, проверка
синтаксиса изменённых Python-файлов и `git diff --check`. Наблюдаемые интервалы
детектора остались прежними, включая известную потерю движения в конце видео.

## Ограничения

- Проверка видео пока ограничена успешным кодом выхода и непустым файлом;
  проверка медиапотоков в приложении относится к пунктам 11–12.
- Атомарная публикация требует жёстких ссылок; FAT/exFAT не поддерживаются.
  На неподдерживаемой файловой системе операция выдаёт ошибку и не публикует
  частичный результат. Для этого сценария есть автоматическая проверка.
- После SIGKILL/сбоя питания временная папка может остаться; следующий запуск
  её не переиспользует. Гарантия сохранности при аппаратном сбое диска не заявлена.
- Готовые сегменты при сбое последующего сегмента сохраняются; задача целиком
  не является одной транзакцией. Полноценная отмена процессов — пункт 5.
- Правила старых имён могут исключить одноимённый пользовательский файл при
  выборе папки; явный выбор файла обходит этот фильтр.
- Многопоточность интерфейса и диагностика внешних программ исправляются
  в следующих пунктах. Основной сценарий проверен на macOS; Windows/Linux
  и настоящая GPU-обработка пока не проверены.

и понятные сообщения с сохранением диагностического вывода.
