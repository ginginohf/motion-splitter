# Этап 14 — пакетная обработка и отчёт

Обе задачи используют общий цикл _run_batch. Порядок входного списка сохраняется
(папка в GUI уже сортируется). Ошибка отдельного файла фиксируется, следующий
файл обрабатывается. Неисправные инструменты/модель на общей предварительной
проверке, невозможность создать папку запуска или записать отчёт останавливают
задачу. Отмена не переходит к следующему файлу.

## Отчёт

В каждой папке запуска создаётся report.json, формат schema_version=1:

- Режим, параметры запуска, общий статус, UTC-время начала/конца и elapsed_sec.
- Counts: success, skipped, failed, cancelled, not_started, running.
- Outputs_total: число опубликованных файлов, включая результаты частично
  выполненных исходников. Это отдельная величина от числа исходных файлов.
- Для каждого исходника: путь, статус, время, найденные интервалы движения,
  фактический порог, выходная папка, опубликованные файлы, журналы, ошибка/примечание.
- Общая ошибка и каталог журналов предварительной проверки.

Статусы исходников:

| Статус | Значение |
|---|---|
| success | Все запрошенные действия для файла завершены |
| skipped | Движение не найдено и сохранение полного видео отключено |
| failed | Ошибка файла; могут остаться опубликованные результаты |
| cancelled | Обработка этого файла прервана; результаты также могут остаться |
| not_started | Файл ещё не запускался |
| running | Файл обрабатывается; после аварии это незавершённая запись |

Сохранение выполняется до предварительной проверки, перед началом каждого файла,
после его окончания и в конце задачи. Запись: временный файл в той же папке,
flush/fsync, os.replace. При сбое замены предыдущий JSON остаётся читаемым.
Если отчёт записать не удалось, задача получает error, а пользователь видит
сообщение об этом; завершение не объявляется успешным.

При аварии приложения отчёт может остаться running и не содержать последних
результатов текущего файла. Автоматического возобновления/восстановления нет.
Результаты файлов не удаляются из-за ошибки записи отчёта. До создания папки
запуска (включая отмену заранее и пустой список) отчёт отсутствует.
Отчёт содержит локальные пути и параметры, автоматически никуда не отправляется.

## Интерфейс и API

Новое событие summary сохраняется отдельно от ограниченного журнала UIEvents,
поэтому переполнение лога не вытесняет итог. В GUI показаны раздельные счётчики,
число сохранённых результатов и путь отчёта. Единственное конечное событие
сохранено: done/error/cancelled. Промежуточные ошибки идут в журнал, не завершая UI.

JobResult дополнен report_path и counts с совместимыми значениями по умолчанию.
Processed означает success + skipped + failed, а не число успешных файлов.
Cancelled и not_started в processed не входят. При ошибках файлов общий статус
error, при отмене — cancelled, без ошибок — done (в том числе все skipped).
Общая ошибка может быть и при counts.failed=0, например отсутствует FFmpeg.

## Проверки

139 unittest — пройдены. Проверки этапа:

- Настоящие FFmpeg/OpenCV: успешный файл → повреждённый → успешный; пакет продолжается.
- Нет движения без сохранения полного видео: skipped и отсутствие выходных файлов.
- Отмена в середине: success/cancelled/not_started, один terminal.
- Ошибка/отмена после публикации: файл остаётся и присутствует в отчёте.
- Общая ошибка инструмента: все файлы not_started, причина на уровне запуска.
- Отдельное улучшение продолжает пакет после ошибки (нейросеть имитируется).
- Снимки отчёта до работы и между файлами.
- Отказ атомарной замены, остановка после ошибки промежуточной записи,
  ошибка итоговой записи без ложного done.
- Переполнение очереди лога не вытесняет summary.

Настоящий Tkinter: нарезка и имитация улучшения, оба report.json со статусом done,
отображение пути отчёта на обеих вкладках — пройдено. Предыдущие тесты временных
меток, защиты файлов, отмены, настроек и детектора также прошли.

GPU-апскейл, Windows/Linux остаются неподтверждёнными, как в предыдущих этапах.
Отчёт JSON; отдельной таблицы результатов и повторного запуска выбранных ошибок
в интерфейсе пока нет. Следующий этап — темы, компоновка и понятность интерфейса.
