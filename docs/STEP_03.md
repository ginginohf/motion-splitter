# Пункт 3 — запуск инструментов и диагностика

## Изменения

- Новый модуль `external_tools.py`: поиск исполняемых файлов, общий запуск
  процессов без shell и без автоматических повторов, структурированная ошибка.
- Поиск FFmpeg больше не возвращает каталог `ffmpeg`. Локальные кандидаты
  проверяются как файлы с разрешением на запуск, затем используется PATH.
- Явно заданный путь Real-ESRGAN авторитетен: ошибка пути не скрывается
  автоматической подстановкой другой копии программы.
- До анализа проверяется FFmpeg (`-version`, максимум 15 секунд), а при
  улучшении — наличие исполняемого Real-ESRGAN. Обычная нарезка не требует ESRGAN.
- Все команды экспорта, извлечения кадров, апскейла и сборки идут через общий
  runner. stdout/stderr направлены непосредственно в уникальный постоянный файл;
  большой вывод не накапливается в памяти и не блокирует чтение pipe.
- Каждый журнал содержит время UTC, команду в JSON, рабочую папку, этап,
  полный объединённый stdout/stderr и итоговый код выхода. На ошибке выводится
  ограниченный хвост (4 КиБ), полный журнал остаётся доступен.
- Ошибки до запуска процесса и после него (например, публикация результата)
  записываются отдельными application-логами. Сбой записи лога не скрывает
  исходную ошибку в сообщении интерфейса.
- Журналы хранятся в `run/logs`, вне временных каталогов. При прямом вызове
  функций без runner — в `logs` рядом с результатами функции.
- Из GUI убрана цепочка «прямая попытка → любая ошибка → покадровая попытка».
  Обе вкладки используют покадровый маршрут один раз для каждого файла.
  Существующий helper прямого запуска оставлен для явного вызова, но GUI его
  не вызывает. Ошибки helpers теперь передаются вызывающему коду, а не
  превращаются в безымянный `False`.
- На вкладке улучшения проверка инструментов и восстановление кнопки запуска
  защищены `try/finally`; при ошибке предстарта задача не остаётся заблокированной.

## Проверки

`python -m unittest discover -s tests -v`: 28 тестов, все прошли.

12 новых проверок: полный stdout/stderr и метаданные; большой вывод и неверные
UTF-8 байты; однократный запуск при ошибке; отсутствующий бинарник; тайм-аут;
пропуск каталогов при поиске; строгий пользовательский путь; отсутствие прав
на запуск; настоящий `ffmpeg -version`; отказ до обработки при отсутствии
инструмента; повреждённый видеофайл с постоянным логом; отсутствие резервной
попытки после ошибки апскейла.

16 проверок пункта 2 сохранены и адаптированы к передаче ошибок исключениями.
Настоящий FFmpeg проверяет экспорт, сохранение звука и сохранность исходников.
Имитации Real-ESRGAN проверяют ошибки и файловую безопасность; GPU не запускался.

## Границы этапа

- Полная отмена длительных процессов — пункт 5. Тайм-аут есть только у короткой
  проверки запуска FFmpeg; экспорт и апскейл не ограничены 15 секундами.
- Доступность файла Real-ESRGAN не доказывает совместимость модели, драйвера или
  GPU. Эти проверки — пункт 12; сейчас сохраняется реальная диагностика процесса.
- Сообщение указывает точный этап, а причину передаёт оригинальным выводом:
  по одному коду завершения нельзя достоверно отличить модель от ошибки GPU.
- Известная многопоточность Tkinter на вкладке улучшения — следующий пункт 4.
- Проверка медиа после выхода процесса — пункты 11–12; пока проверяется наличие
  непустого результата, как в пункте 2.
- Общий отчёт о пакетной обработке и счётчики успехов/ошибок — пункт 14.
- Проверено на macOS. Windows/Linux и реальный Real-ESRGAN не проверены.
